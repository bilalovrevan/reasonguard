\chapter{Experimental Setup}
\label{ch:experimental-setup}

\section{Datasets}
\label{sec:datasets}

The empirical evaluation uses two publicly available datasets published on
IEEE DataPort by the NES@FIT group at the Faculty of Information Technology,
Brno University of Technology.

The first dataset, \emph{Modbus Dataset for ICS Anomaly Detection}
\autocite{RysavyMatousek2021Modbus}, captures Modbus traffic from a
controlled industrial testbed. The dataset is used for the function code
violation and replay attack event types in the exposé.

The second dataset, \emph{ICS Dataset for Smart Grid Anomaly Detection}
\autocite{MatousekRysavyGrofcik2022SmartGrid}, captures IEC-104 traffic from
a smart-grid testbed. The pipeline currently uses the eon-iec subset of this
dataset; the working file is \texttt{data/raw/sample\_003.csv} with 20\,000
atomic IEC-104 rows.

\section{Language Models}
\label{sec:models}

\subsection{Local Models}
The pipeline runs three local models through Ollama 0.23.3 with 4-bit
quantisation on a CPU-only inference path:

\begin{itemize}
  \item \texttt{llama3.1:8b-instruct-q4\_0} ($\approx$ 4.7~GB on disk).
  \item \texttt{mistral:7b-instruct-v0.3-q4\_0} ($\approx$ 4.1~GB on disk).
  \item \texttt{phi3:mini} ($\approx$ 2.2~GB on disk).
\end{itemize}

Each call uses the same generation parameters: temperature 0.1, top-p 0.9.
Latency on the reference hardware is approximately 11--14 seconds per
prompt for the 7B and 8B models, and approximately 11~seconds for
\texttt{phi3:mini}.

\subsection{Cloud Models}
\label{subsec:cloud-models}

The cloud-model batch uses \texttt{gpt-4o-mini} (OpenAI) and
\texttt{gemini-1.5-flash} (Google). The runner at
\texttt{src/cloud\_llm\_runner.py} is implemented as a thin urllib client and
gracefully skips when the corresponding API key environment variable is
unset. The cloud batch is deferred to weeks 13--14 to keep the API spend
predictable and to allow the local-model results to stabilise the violation
taxonomy first.

\section{Prompt Design}
\label{sec:prompts}

Every prompt comprises a fixed analyst system prompt and a user prompt that
embeds the JSON formal bound together with the explicit lists of allowed,
required, and forbidden claims. The user prompt is intentionally verbose so
that any deviation in the LLM output is a deliberate model failure rather
than a prompt-engineering shortfall. Three prompt variants will be compared
in a 20-sample pilot at the start of the W11 evaluation block; the
production variant is the one used to produce all responses reported in
Chapter~\ref{ch:results}.

\section{Stratified Sampling}
\label{sec:stratified-sampling}

To compare model behaviour across event types, prompt selection uses
stratified sampling: \texttt{src/prompt\_builder.py} samples a fixed number
of bounds per proxy event type (controlled by the
\texttt{REASONGUARD\_PER\_EVENT\_TYPE} environment variable, default 20).
The sampler is seeded by \texttt{RANDOM\_SEED} so the selection is
reproducible. The current production run uses 25 bounds per event type,
yielding 100 prompts in total across the four observed event types.

\section{Evaluation Protocol}
\label{sec:protocol}

The evaluation has three populations.

\paragraph{Synthetic regression set.}
For every selected bound the generator produces a small set of canonical
responses, one per V class plus one clean response. This set is the source
of truth for the V1--V5 detector unit tests. It is not used to draw
conclusions about model behaviour.

\paragraph{Local-model batch.}
The three local models each produce one explanation per prompt. The
resulting (model, event\_type) cells are the production data analysed in
Chapter~\ref{ch:results}.

\paragraph{Cloud-model batch.}
The two cloud models each produce one explanation per prompt. The results
are added to the same combined report and the same per-event-type analysis.

The verification step is the same for all three populations: every response
is processed by \texttt{src/reason\_guard\_checker.py}, which produces the
V1--V5 violation set, the severity rating, and (when spaCy is installed) the
per-claim three-state verdicts.

\section{Manual Annotation}
\label{sec:manual-annotation}

The exposé requires manually annotated explanation pairs for the M4
milestone (200 pairs at week 14). The first 50-row pilot batch is generated
by \texttt{src/manual\_annotation.py} and saved to
\texttt{annotation/annotation\_batch.csv}; the annotator fills in
\texttt{human\_label} and \texttt{human\_severity} columns and saves the
result as \texttt{annotation\_results.csv}. The
\texttt{src/evaluation\_metrics.py} module then computes per-class
precision, recall, F1, accuracy, the confusion matrix, and Cohen's $\kappa$.

\label{sec:reproducibility}
